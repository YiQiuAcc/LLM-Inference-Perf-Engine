# LLM-Inference-Perf-Engine: 私有化大模型推理网关与流式性能工程系统

本路线图系统性地记录了本项目从零构建模型容器底座、上层高负载应用开发、到最终进行全栈性能调优与工程化落地的演进过程。

---

### 阶段一：高可用大模型推理底座建设（容器化与异构拓扑）

- **状态：已完成**
- **核心任务：** 解决物理 GPU 资源向容器内部透传的隔离与挂载问题，搭建统一底座。
- **具体实践：**
  - 编写 `docker-compose.yml`，配置 `deploy.resources.reservations.devices` 正确透传 NVIDIA 硬件驱动。
  - 完成 Ollama 与企业级高并发后端 vLLM 的镜像部署，打通本地物理显存到容器内部推理服务的链路。

### 阶段二：自研流式性能测试框架开发（高精度指标度量）

- **状态：已完成**
- **核心任务：** 攻克开源传统测试工具不支持 LLM 流式语义（SSE）解析的痛点，提供高精度的性能衡量手段。
- **具体实践：**
  - 在 `src/llmp/core/` 中抽象出多线程网络通信层，通过底层 `client.py` 接管流式 HTTP 块的解析。
  - 引入高精度计时器，在首个 SSE 块返回时触发计算，精准解耦出 **TTFT (首字延迟)** 与 **ITI (间字延迟)**。
  - 设计包含系统冷却时间的梯度并发调度算法（`src/llmp/runners/stress.py`），为后续的基准测试排除缓存与残余显存碎片干扰。

### 阶段三：长文本业务应用接入（构建真实长上下文负载场景）

- **状态：规划中**（原 `llmc` 概念，落地位置 `src/llmp/loadgen/`）
- **核心任务：** 开发 `loadgen`（本地代码分析助手）作为项目的真实上层业务负载，打破单纯空载测试的局限性。
- **具体实践：**
  - 实现本地代码仓库（支持 Python、C# 项目）的自动化递归扫描与结构解析。
  - 编写长文本上下文拼装引擎，将多文件源码、结构树与 Review 提示词进行 Token 级对齐拼接，构建出 8K-32K 以上的稳定长文本请求。
  - 将 `loadgen` 的业务链条通过 `llm-perf review` 统一入口路由至网关层，以真实的高负载长文本业务流对底层推理服务的 KV Cache 空间进行压迫。

### 阶段四：网络协议调优与智能反向代理（网关层性能工程）

- **状态：已完成**
- **核心任务：** 解决应用层 `loadgen` 在接收大规模长文本响应时，网关层产生的网络堆积与流式卡顿问题。
- **具体实践：**
  - 配置 Nginx 作为推理集群的反向代理，接管全部入站业务流量。
  - **针对性调优：** 显式关闭 `proxy_buffering`，调大 `proxy_read_timeout` 与保持长连接（Keep-Alive），消除因缓冲区满导致的 Token 传输断续问题。

### 阶段五：可观测性监控体系建设（监控指标白盒化）

- **状态：已完成**
- **核心任务：** 建立物理硬件（GPU）与软件后端（推理引擎）的联合监控面板，在压测时具备全链路看清系统状态的能力。
- **具体实践：**
  - 引入 NVIDIA DCGM Exporter，将底层显存占用、SM 利用率、温度、功耗等物理指标暴露给 Prometheus。
  - 针对 vLLM 推理引擎，抓取其内部动态暴露的运行时指标（如：已分配的 KV Cache Block 比例、请求队列排队长度、系统吞吐量）。
  - 在 Grafana 中定制白盒化看板，将压测脚本输出的 TTFT/Throughput 曲线与硬件层面的显存/GPU 利用率进行多维时序对齐。

### 阶段六：容量规划实验与性能调优白皮书

- **状态：迭代中**
- **核心任务：** 运行全链路实验，通过定量分析找出当前有限硬件资源下的性能拐点，并形成可沉淀的调优方法论。
- **核心实验方案：**
  - **实验 1（长文本挑战）：** 启动 `loadgen` 扫描大型项目，在长上下文下观察显存（KV Cache）何时因碎片化引发系统崩溃或剧烈排队，以此对比评测 Ollama 与 vLLM（PagedAttention 机制）在长文本处理上的优劣。
  - **实验 2（并发极限发现）：** 结合自研压测脚本，记录并发数上升时，系统 TTFT 延迟由平缓走向陡峭的“拐点（Knee Point）”，从而得出当前硬件下模型的最大合理并发承载量。
  - **文档化：** 将上述测试数据与系统参数优化项（如推理引擎的预读 Chunk 尺寸、显存利用率上限参数设定）沉淀在 `docs/` 下，形成《私有化大模型性能工程白皮书》。
